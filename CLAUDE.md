# CLAUDE.md — channel-radar

## Layer boundaries

- `app/parser/` — knows nothing about the DB or FastAPI. Accepts HTML/bytes, returns plain
  dataclass/Pydantic objects (`ParsedChannel`, `ParsedPost`). Functions must be testable
  without network access and without a DB session.
- `app/services/` — business logic (ingest, analytics, AI). Knows nothing about HTTP/FastAPI:
  no `Request`, `Response`, `HTTPException`, `BackgroundTasks` inside a service. A service
  accepts plain types/DTOs and a DB session, returns plain types/DTOs or raises its own exceptions.
- `app/web/routes_*` — input validation, calling a service, rendering the response (HTML or JSON)
  only. No business logic, no direct SQL/ORM queries bypassing the service layer.

## Tests

- Network access is forbidden. A guard fixture breaks the `httpx` transport in `tests/` — no test
  may make a real HTTP or LLM call.
- The parser is tested against saved fixtures in `tests/fixtures/` (HTML pages from `t.me/s/*`).
- All LLM calls are mocked (fake client), never hitting the Gemini API.

## Migrations

- The DB schema changes only via Alembic: `alembic revision --autogenerate -m "..."`.
- Never use `Base.metadata.create_all()` in production — only `alembic upgrade head`.
- Revision names must be descriptive (what actually changed), not an autogenerated hash without context.

## Data

- Facts (`channels`, `posts`) and measurements (`*_snapshots`) are not mixed: facts are inherently
  immutable, measurements are append-only rows over time.
- A metric snapshot is written only if the value changed relative to the last record for that
  same object (dedup by value) — otherwise the table bloats with identical rows on frequent cron runs.
- A post's natural key is `(channel_id, message_id)` together, a UNIQUE constraint in the DB.

## Secrets

- All secrets/config go only through `app/config.py` (`pydantic-settings`), read from env.
- Only `.env.example` with no real values is in git. `.env` is in `.gitignore`.
